### Decisions made (owner, date)

- **Simplified project direction:** The project will focus on a straightforward food-finder website rather than a cooking simulation or minigame. The main purpose is to help York University Markham students discover nearby food options based on their preferences. Owner: T.H.E. Team. Date: November 2026.
- **Four-screen initial website:** The first website version will establish the welcome page, food category selection, budget selection, and dining preference selection before more advanced functionality is added. Owner: T.H.E. Team. Date: November 2026.
- **Front-end technology:** The website will use HTML, CSS, and vanilla JavaScript to keep implementation manageable for the project and appropriate for the team's current experience. Owner: T.H.E. Team. Date: November 2026.
- **Gradual development:** The website will be developed through separate milestones instead of implementing all planned features at once. Owner: T.H.E. Team. Date: November 2026.
- **Restaurant recommendations postponed:** Restaurant information and matching functionality will be introduced in a later milestone after the initial selection flow is developed. Owner: T.H.E. Team. Date: November 2026.

### Challenges & risks (severity, mitigation)

- **Keeping the implementation manageable — Medium severity:** The original project direction included more complicated simulation and game functionality. This was simplified into a food-finder website with a smaller number of screens and interactions. The team will continue developing the website in milestones to avoid unnecessary complexity.
- **Incomplete functionality — Medium severity:** The initial website establishes the main screens and navigation, but the full interactive preference-selection process and restaurant recommendation functionality are not yet implemented. These features will be developed in the next milestones.
- **Testing not yet completed — Medium severity:** Formal functional and usability testing has not yet been conducted. The team has documented a testing plan and will complete the planned checks before considering the initial implementation fully validated.
- **Placeholder images — Low severity:** The initial website uses placeholders for food-related visuals. Group-provided images will be added during later development.
- **Keeping documentation consistent — Low severity:** Some earlier documentation described the original simulation concept. The relevant Wiki pages have been updated to reflect the simpler food-finder direction and current implementation.
